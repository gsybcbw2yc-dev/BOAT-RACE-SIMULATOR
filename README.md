# BOAT RACE SIMULATOR v0.6.0

仮想資金だけで競艇の予想・資金管理を楽しむ、ビルド不要のブラウザゲーム。

## 起動

- `index.html` と `core.js` を同じディレクトリに置いてブラウザで開くか、GitHub Pages で公開する。研究ラボはGitHub Pagesで開く。
- 外部ライブラリ、API キー、バックエンド不要。同一サイトの静的ソース以外へ通信しない。
- `private-race-pack.json` はユーザー本人用のデータ。公開リポジトリへ追加せず、トップ画面の「レースデータを読み込む」から選択する。未読み込み時は架空プロフィールのデモになる。
- データ読み込み後に新規の架空モードを開始すると、実在選手の保存プロフィールを使用する。開始済みの架空ゲームは途中でプロフィールを変えない。

## AI研究ラボ（QLAB-1.1）

トップ画面の「研究ラボを開く」から、通常プレイと独立したQ学習を実行できる。PC推奨。Web Workerで数値計算を行い、アニメーションを描画しない。架空の実験設定は学習1,000〜1,000,000R、評価500〜100,000R（ブラウザ選択肢）。

### 現行モデル凍結移植（本番V58）

- V4基準型 `V4-PL-2026-10-12`、V6展開型 `V6-SCENARIO-2026-11-16`、V6統合型 `V6-INTEGRATED-2026-11-16` を選択できる。非公開GitHub BOAT-ANALYZER-V6 の `simulator/private-model-pack-v58.json` を本人がダウンロードし、研究ラボで読み込む。公開リポジトリには推論コード・重み・選手履歴・実データを含めない。
- 本番ソース `11dab445ac57bdbd46e2ef9114dcc505de9f984a` の推論コードと固定モデルをそのままパック化。SHA-256で一致を確認してから端末内のWorkerで実行。V6の適用条件を満たさない場合、V4への無告知の代替はせず停止する。架空選手IDは実在選手と区別し、欠損の歴史特徴はモデル本来の処理に任せる。
- 実データを使用する場合は非公開GitHub `data/direct/sync/YYYY-MM-DD/*-*.json` の同期バッチを複数指定する（manifestは除く）。品質A/B、締切前の予測・公式オッズ、公式確認済み通常結果・払戻、追加出走項目を検証して開催日順に分割（学習日と評価日は重複しない）。訂正台帳を優先し、旧データ、C、特殊結果、欠損、競合は対象外。入力元の公開時刻や前向き予測の独立検証は別途必要。
- Q表はモデルごとに独立して学習、評価時は凍結。比較する際は同一シード・設定・データを指定する。元モデルの重み・本番Siteは変更しない。

- 架空モードは現行のSECTOR-1.0・3連単合成オッズを共通使用。選択した予測モデルは固定。学習と評価は別の再現可能なシード名前空間・一意のレースID。
- 48Rごとに仮想資金10万円へリセットするエピソード式、借入・生活費なし。残高・ドローダウン・確率・合成オッズの特徴・エピソード内の残り時間を離散化し、見送りと5つの固定購入アクションから選択。報酬＝仮想収支−0.25×ドローダウン増加（1,000円単位）。
- 学習には探索を使用。評価はQ表を凍結し、同じ未使用架空レースをQ学習、全見送り、上位1点、上位10点の固定戦略に適用する。回収率だけでなく収支・最大DD・参加率・赤字エピソード率を比較する。
- 結果・Q表はJSONに出力可能。スマートフォンから結果JSONを開いて表示できる。途中停止時のQ表は保存しない。通常プレイのセーブ、私的レースパック、本番BOAT ANALYZERを変更しない。
- 架空レースは現実の予測精度や利益を実証しない。実データ評価も事後検証であり、将来の利益を保証しない。予測モデル学習、学習済み戦略の本番転送は行わない。評価シードの選び直しによる過適合にも注意。

PCでNode.jsを利用できる場合のCLI（追加npmパッケージ不要）：

```sh
node lab.cjs --train 100000 --evaluate 10000 --seed 20261121 --out boat-q-report.json
node lab.cjs --model integrated --model-pack private-model-pack-v58.json --train 1000 --evaluate 500 --out v6-q-report.json
```

出力先が存在する場合は上書きせずに終了する。

## 実装済み

- 実戦 / 独立検証の2つの入口。架空 / 実在の別々の4セーブ。AIの公開タイミングを分離。
- 48R/日の架空開催、締切時刻順の進行、任意参加・見送り、就寝、生活費3難易度。
- 初期資金10万円、赤字時の1万円単位借入、上限10万円、日利1%、任意返済、純資産7日連続負でゲームオーバー。
- 全7舟券種、通常・フォーメーション・ボックス・流し・オッズ投票、100円単位の一括・個別金額設定。展開された買い目の重複除外、既存ベットとの合算、点数・購入合計・残高の確認。架空オッズ変動、確定結果の払戻、速度可変Canvas観戦とスキップ。
- 観戦は共通のスタート／ゴールラインを通る3周のコース。先頭艇に連動する周回数（0/3〜3/3）、途中順位、艇の向き・航跡と各艇のゴールを模式描画する。実在の確定着順・払戻、精算処理は維持。
- ピットアウト、待機・進入、助走、大時計（白針60秒・黄針12秒の模式時計）、スタート、ST表示、1M・2M、ゴールまで連続観戦。自動カメラ／全景固定、速度1・2・4倍、生成・推定実況、順位・周回表示。
- 架空レースの新しい区間走行モデル `SECTOR-1.0`：ST・コース・勝率・モーター・展示・風波・旋回半径・直線速度・引き波の仮説によって6艇の24区間の通過時間を生成。1M出口の順位と最終着順はこの時間から決まる。予測モデルは変更せず、既存の結果・セーブは維持（未実施の架空レースから新方式）。
- 結果画面で生成ST・1M出口順・1/2/3周タイムを確認可能。研究ログとCSVに生成方式、生成区間タイムを追加。モデル評価は旧生成方式と新生成方式を分離。
- 3連単120通り、1–3着確率、実験モデル要因寄与、期待回収倍率、第1M模式図、決まり手の仮説確率。任意のプレイヤー予想記録。
- 参加・見送り・未選択を区別して研究ログ生成。モデル別指標、券種別、会場別、最大ドローダウン、CSV/JSON出力。
- IndexedDB自動保存（不可の場合LocalStorage）、セーブファイルのエクスポート・インポート。

## データと検証上の制約

- 実在リプレイは別途取得したデータパックから、締切前に保存された予測・3連単オッズ・通常結果・公式3連単払戻の照合が成立したレースのみを読み込む。選手の平均STが欠損する場合、実験モデルで当該効果をゼロにし、架空カードの抽選対象から除く。実データはこの公開リポジトリに含めない。
- 入力元の公開時刻は独立検証されていない。アーカイブの全舟券払戻と保存ST・進入を使用するが、3連単以外の締切前オッズと第1Mの現実の順位は未収録。公式照合済みと呼べるのは3連単の着順と払戻のみ。実在リプレイの途中順位、航跡、区間タイムおよび実況は推定再現であり、研究ログの実測値として保存しない。正常完走の6艇レースのみ対象（F・Lや事故・返還の生成は未対応）。
- 実験モデル EXP-PL-0.1 は事前入力による仮説モデルで、実データで学習したモデルではない。結果生成・市場・予測は別アルゴリズム。SECTOR-1.0 も実測航跡や実際の決まり手分布で校正していない仮説モデル。架空レースはモデルの予測性能を証明しない。
- 通常ゲームの実在モードは引き続きV4の締切前保存分布との比較に使用する。研究ラボ（QLAB-1.1）では別途非公開パックでV4・V6の固定推論を実行できる。実在リプレイは取得済みの日付とレースに限定される。
- 実在オッズは原データの単一スナップショットを表示し、変動を捏造しない。全7券種の正しい払戻で精算するが、未保存オッズは未保存と表示する。
- 研究ログはクライアント側のため、再現可能性のある学習用データであり、改ざん耐性・厳密な前向き監査は保証しない。公開版はソースコードだけを配布すること。
